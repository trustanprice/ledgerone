# AGENTS.md — dbt/

Fleet: [../AGENTS.md](../AGENTS.md)

## Purpose

The entire transformation, testing, and documentation layer for LedgerOne.
Everything from "typed raw data" through "answers to business questions"
lives here, as a single dbt project (`profile: ledgerone`, target `dev`,
adapter `duckdb`).

## Layout

```
dbt_project.yml, profiles.yml   — project + connection config
models/staging/                 — stg_* : typed, 1:1 with raw sources
  _sources.yml                  — source defs (external_location -> parquet)
  _staging.yml                  — schema tests + descriptions
models/marts/core/               — the star schema
  dim_date, dim_customer, dim_account, fact_transactions
  _core.yml
models/marts/reporting/          — one model per business question
  monthly_revenue_and_refund_rate, net_payout_by_period,
  top_customers_by_transaction_volume, avg_transaction_value_trend,
  account_running_balance
  _reporting.yml
tests/                           — singular (custom) tests
docs/lineage.md                  — static export of the dbt docs lineage graph
target/, logs/                   — build artifacts, gitignored, don't hand-edit
```

Materialization: staging = `view`, marts = `table` (set in `dbt_project.yml`,
not per-model). Custom schemas: `main_staging` and `main_marts` (dbt's
default `<target_schema>_<custom_schema>` naming — DuckDB schemas, not
separate databases).

## Sources: no load step

Raw parquet is queried directly — `meta.external_location` in
`_sources.yml` points `{{ source('raw', 'events') }}` etc. straight at
`data/raw/events.parquet` (DuckDB reads Parquet natively). There's no seed
or load stage; `dbt build` is the first thing that touches the raw files.

## Required env vars

Every `dbt` invocation needs:
- `LEDGERONE_DB_PATH` — absolute path to the DuckDB file.
- `LEDGERONE_RAW_DIR` — absolute path to `data/raw/`.

The `Makefile` at the repo root sets both. If invoking dbt manually from
inside `dbt/`, the relative-path defaults in `profiles.yml` /
`_sources.yml` (`../data/...`) work, but only when your cwd is `dbt/` —
prefer running through `make build` / `make test` to avoid path bugs.

## Testing philosophy

`dbt test` (or `dbt build`, which runs models then tests) is the only
correctness gate in this project — it replaced a hand-written Python
validation script. Two singular tests carry logic that schema tests can't
express:

- **`assert_refunds_balance_against_purchases.sql`** — this is a
  **single-entry ledger**, not double-entry: each event posts once against
  the user's cash account, with no offsetting platform-side account. So a
  global `sum(credits) = sum(debits)` invariant does *not* hold by design —
  don't add one. The one place a real balance invariant applies is a
  reversal: every REFUND must exactly offset the PURCHASE it references.
  That's what this test checks.
- **`assert_amounts_are_positive.sql`** — `amount` is always positive;
  `posting_type` (CREDIT/DEBIT) carries the sign, not the amount column.

When adding a new mart, add schema tests to its `_*.yml` at minimum
(`not_null`/`unique` on the grain column); add a singular test only when the
invariant can't be expressed declaratively.

## No dbt packages

`dbt deps` / dbt_utils etc. are deliberately not used — `dbt run` and
`dbt build` never call `dbt deps`, and there's no `packages.yml`. This
environment had SSL/network trouble reaching the dbt package hub during
setup. Use dbt-core's built-in global-project macros instead (e.g.
`{{ dbt.hash(...) }}` for a deterministic surrogate key) or plain DuckDB
SQL (`generate_series`, `qualify`, window functions). If you genuinely need
a package later, confirm `dbt deps` can actually reach the hub in this
environment before depending on it.

## Docs

`dbt docs generate` produces `target/catalog.json` / `manifest.json` (used
by `dbt docs serve` for the interactive lineage UI — not run headlessly
here). `docs/lineage.md` is a static Mermaid export of the same DAG,
regenerated by hand from `manifest.json`'s `parent_map` whenever models
change — see the comment at the top of that file for the extraction
snippet.

## Connects to

- Reads `data/raw/*.parquet`, written by `src/generate_data.py`.
- Writes `main_marts.*`, read by `src/generate_report.py`.
